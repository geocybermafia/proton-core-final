## 1. Proton-ის მიზანი და ძირითადი არქიტექტურა

Proton არის თანამედროვე მრავალფუნქციური ვებ-ეკოსისტემა, რომელიც აერთიანებს:
- **Market Hub** — P2P ელექტრონული კომერციის პლატფორმა (პროდუქტების კატალოგი, რეალურ დროში ჩატი მყიდველსა და გამყიდველს შორის, კალათა, პირდაპირი შეკვეთების ფორმირება).
- **Creative Studio** — მარკეტინგული კონტენტის, სათაურების, სარეკლამო კამპანიებისა და სლოგანების გენერირების ხელსაწყო.
- **Clips / Reels** — ვიდეო კონტენტის გაზიარებისა და პროდუქტების ვიზუალური დემონსტრაციის მოდული.
- **Opportunities Engine** — გამყიდველის ანალიტიკური მექანიზმი, რომელიც აფასებს მარაგებს (დაბალი ნაშთი `<= 2`), ბოლო 72 საათის აქტივობას და გამოუყენებელ სარეკლამო კამპანიებს.
- **Hardware Diagnostics** — სისტემური რესურსების, მეხსიერებისა და კავშირის დიაგნოსტიკის პანელი.

### ფინანსური მოდელი და ტრანზაქციების ბუნება
> **მნიშვნელოვანი შენიშვნა:** Proton-ის არსებული შეკვეთების სისტემა ემსახურება პირდაპირ მყიდველსა და გამყიდველს შორის შეთანხმებას (P2P Direct Agreement / Cash on Delivery / Direct Transfer).  
> **ამჟამად Proton მომხმარებლის თანხებს არ ინახავს (No Escrow / No Wallet Custody).**  
> შეკვეთის გაფორმებისას სისტემაში იქმნება შეკვეთის ჩანაწერი (`/orders`), რომელიც აფიქსირებს ნივთის რეზერვაციას, საკონტაქტო მონაცემებსა და შეთანხმებულ პირობებს.

### ტექნოლოგიური დასტა
- **Frontend:** React (TypeScript), Vite, Tailwind CSS, Lucide Icons.
- **Backend API:** Node.js / Express (`serverApp.ts`), Vite Middlewares.
- **მონაცემთა ბაზა:** Google Cloud Firestore (რეალურ დროში მონაცემთა სინქრონიზაცია, უსაფრთხოების წესები `firestore.rules`).
- **ავთენტიფიკაცია:** Firebase Authentication (Guest, Email/Password, Google OAuth).
- **ფაილების შენახვა:** ორდონიანი ჰიბრიდული არქიტექტურა:
  - პირველადი: Supabase Storage (`listing-images`, `clips` ბაკეტები).
  - რეზერვი (Fallback): Firebase Storage.

## 7. ადმინისტრატორის უფლებების მდგომარეობა (Admin Privileges Status)

#### [#009] Firebase ადმინისტრატორის უფლებების რეალური გააქტიურება
- **სტატუსი:** ⬜ ჯერ არ დაწყებულა (კოდის ლოგიკა და სკრიპტი მზადაა, გასაშვებია რეალურ ანგარიშზე).
- **დანიშნულება:** მომხმარებლის UID-ზე Firebase Custom Claim `{ admin: true }`-ის მინიჭება.
- **არსებული მდგომარეობა:**
  1. `firestore.rules`-ში `isAdmin()` ფუნქცია მკაცრად ამოწმებს `request.auth.token.admin == true`.
  2. ჩვეულებრივ მომხმარებელს არანაირი გზით არ შეუძლია საკუთარი თავის ადმინისტრატორად გამოცხადება.
  3. `scripts/` საქაღალდეში არსებობს ადმინის აქტივაციის ლოგიკა Firebase Admin SDK-ის მეშვეობით.
- **დარჩენილი მოქმედება:** რეალური ადმინისტრატორის UID-ის დაფიქსირება და ერთჯერადი სერვერული სკრიპტით Custom Claim-ის მინიჭება, რასაც მოჰყვება კლიენტზე `auth.currentUser.getIdTokenResult(true)` Force Refresh.
